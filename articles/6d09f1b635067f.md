## はじめに

この記事では、連携から最初の記事ファイル作成までの流れを記録します。

## 今日やったこと

- 記事用のGitHubリポジトリを作成した
- Zennの「GitHubからのデプロイ」でリポジトリを連携した
- ローカルにクローンして、Zenn CLIを導入した
- `npx zenn new:article` で最初の記事ファイルを作成した

## 手順

### 1. リポジトリをクローンする

```
git clone https://github.com/<ユーザー名>/<リポジトリ名>.git
cd <リポジトリ名>
```

### 2. Zenn CLIを導入する

```
npm init --yes
npm install zenn-cli
npx zenn init
```

`articles/` と `books/` フォルダができます。

### 3. 記事を作成する

```
npx zenn new:article
```

`articles/` にMarkdownファイルが作られます。先頭の `title` や `topics` を埋めて、本文を書きます。

### 4. pushする

```
git add .
git commit -m "記事の下書きを追加"
git push origin main
```

`published: true` にしてpushすると、Zennに自動で公開されます。

## 調べたこと

- 草になるのは、GitHubに登録したメールアドレスで、デフォルトブランチにpushしたコミット
- Zennのスクラップや、Webエディタで書いた記事は草にならない
- GitHub連携で管理する記事・本は、pushした分が草になる

## 試したこと(失敗含む)

失敗1: pushで認証エラー
`git push origin main` で `Password authentication is not supported for Git operations.` と出て失敗した。
GitHubのパスワードを入れていたのが原因で、HTTPS接続ではPersonal Access Token(`repo` 権限)を使う必要があった。
トークンを作り直して貼り付けたら成功した。

### 失敗2: ブランチ名の打ち間違い
`git push origin mai` と打ってしまい、`src refspec mai does not match any` となった。
`main` のnが抜けていただけだった。

### 気づいたこと
- パスワード入力欄は、貼り付けても画面に何も表示されないが、正常
- `nothing to commit` は、すでにコミット済みという意味で、エラーではない

## 現時点の結論

GitHub連携にすると、記事の下書きを少しずつpushするだけで、執筆の過程がそのまま草になります。
